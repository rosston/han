### CLI contract pins (fetched 2026-10-16 from the vercel-labs/skills README; npm `skills` v1.7.0)

These pin the spec's T# mechanics to concrete forms. Reuse them; do not re-fetch.

- **Internal-skill marker (pins T3):** frontmatter `metadata:` / `  internal: true`. Opt-in:
  `INSTALL_INTERNAL_SKILLS=1` (or `true`) shows and installs internal skills. Source: skills README,
  "Optional Fields" and "Environment Variables".
- **Manifest skills declaration (pins D6/T1):** a `marketplace.json` plugin entry accepts
  `"skills": ["./skills/review", "./skills/test"]` — path strings relative to the entry's `source`
  directory. Declared paths are searched at their declared depth, outside the depth-3 catalog walk.
  The reference repo mattpocock/skills declares its own `.claude-plugin/plugin.json` `skills` array the
  same way (paths like `./skills/engineering/ask-matt`). For Han: entry `"source": "./han-coding"` gets
  `"skills": ["./skills/tdd", ...]` resolved against `./han-coding`.
- **Discovery containers (pins T1):** the CLI walks container directories (root `SKILL.md`, `skills/`,
  `.claude/skills/`, `.agents/skills/`, ~45 more) up to three levels deep; `.claude-plugin/marketplace.json`
  and `.claude-plugin/plugin.json` declarations are also discovered; a recursive search runs only if
  nothing is found. Han's `.claude/skills/` is a standard container, so the 2 maintenance skills reach
  discovery through it (matches D4).
- **Install (pins T2):** install copies or symlinks exactly the skill folder into the agent's skills
  directory (project `./<agent>/skills/`, or global `~/.<agent>/skills/` with `-g`).
- **Update (pins D8):** `npx skills update [skills]` refreshes installed skills from the same source.
- **Permission declarations:** the CLI's compatibility table shows `allowed-tools` unsupported on Cline
  and Zencoder — corroborates the spec's per-call-approval degradation row.

### Agent-skills specification pins (fetched 2026-10-16 from https://agentskills.io/specification)

- File references use relative paths from the skill root: `See [the reference guide](references/REFERENCE.md)`;
  `Run the extraction script: scripts/extract.py`. Keep file references one level deep from `SKILL.md`.
- The frontmatter schema defines no skill-path variable (fields: `name`, `description`, `license`,
  `compatibility`, `metadata`, `allowed-tools`).
- `name` must match the parent directory name (corroborates the guard's name==folder assertion).
- `metadata` is an arbitrary key-value map for client-specific properties (the CLI's `internal: true`
  marker fits).
